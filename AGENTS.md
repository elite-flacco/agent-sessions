## Relay architecture

- `src/collector/adapters/` contains provider-specific JSONL normalization. Adapters must never return raw prompts, responses, reasoning, credentials, or tool arguments. Session hierarchy is normalized into `parent_external_id`, `session_kind`, `agent_label`, and `agent_depth`: Codex uses `session_meta.parent_thread_id`, Claude sidechains use `agentId` as the child identity and `sessionId` as the parent, and Zcode uses `session.parent_id`/`task_type`. Titles prefer provider-authored metadata: Codex reads `threads.title` from `~/.codex/state_5.sqlite` through `src/lib/codex-db.ts`; Claude prefers the latest `custom-title`, then latest `ai-title`; both fall back to the first meaningful user message. The collector reconciles Codex database titles after every full scan because renames do not change rollout JSONL. `CODEX_STATE_DB_PATH` is the Codex test seam and `__resetCodexDbCache` clears connections between tests. The Zcode adapter resolves authoritative titles and missing `cwd`/`repository` values from Zcode's own session database (`~/.zcode/cli/db/db.sqlite`, opened read-only via `src/lib/zcode-db.ts`); after file scans the collector reconciles Zcode metadata and status from the database's message/part tables, including database-only sessions and unresolved `AskUserQuestion` tools. `ZCODE_DB_PATH` is the Zcode test seam and `__resetZcodeDbCache` clears connections between tests. Branch stays JSONL-derived because Zcode's schema has no git field.
- Session status preserves provider evidence: explicit completion markers produce `completed`, explicit abort/cancel markers produce `interrupted`, explicit failures produce `needs_attention`, and an unresolved Zcode `AskUserQuestion` tool also produces `needs_attention`. Unterminated sessions are `running` for 10 minutes after their last update and then read as `incomplete`; inactivity alone must never imply interruption. Overview includes attention sessions updated today or during the entire previous local calendar day.
- `src/collector/index.ts` owns idempotent source fingerprinting, persistence, and filesystem watching. Full scans and the watcher hold durable leases (`src/collector/lock.ts`, `collector_leases` table) so two processes never ingest concurrently; concurrent in-process syncs share one run. Per-adapter scan state lives in `adapter_scans`.
- `src/db/` owns the versioned SQLite/Drizzle schema; generated migrations live in `drizzle/`. Schema changes must update both `src/db/schema.ts` and the bootstrap SQL in `src/db/client.ts`, then run `npm run db:generate`. `src/db/migrate.ts` establishes a migration baseline for databases created by the original bootstrap SQL before applying newer migrations.
- `src/lib/queries.ts` is the server-side read boundary for dashboard data. It imports the SQLite client, so client components may import **types only** from it; runtime values shared with client code belong in `src/lib/types.ts`, `src/lib/labels.ts`, or `src/lib/format.ts`. Session status is derived at query time (`running` goes stale to `incomplete` after 10 minutes without updates) — do not trust the stored status column for presentation.
- Detailed transcripts are never persisted. `sessions.source_path` links normalized metadata back to its original JSONL file, and `src/lib/transcript.ts` reads supported user/assistant messages and tool arguments/results on demand for `/sessions/[id]`; Zcode sessions instead prefer Zcode's read-only `message`/`part` tables so deleted rollout files and event-only subagent JSONL remain readable. Keep common credential redaction in that boundary, exclude raw reasoning records, and do not pass `sourcePath` into client-side list views.
- Usage and cost: adapters emit normalized per-model usage (`ModelUsage`: uncached input, output, cache read/write, optional provider-reported cost) persisted in `session_model_usage`. Dollar costs are never stored — `src/lib/queries.ts` derives them at read time from `src/lib/pricing.ts`, a checked-in, client-safe pricing table with per-model rates, effective dates, and source URLs. A session gets a dollar figure only when every usage row is priced (reported or table match); otherwise it reads "unavailable" and is excluded from dollar aggregates. Keep new pricing entries dated and sourced.
- Pages: `/` Overview (`overview-view.tsx`; patterns via `getOverviewPatterns()` — activity heatmap, session-length histogram, week cost-at-a-glance), `/sessions` combined Sessions/Projects browser (`dashboard.tsx`) with server-side throttled ingestion on each 15-second refresh and subagents nested beneath main sessions, `/sessions/[id]` full transcript detail plus parent/child navigation (`session-detail.tsx`), and `/usage` (`usage-view.tsx`). `/projects` redirects to `/sessions?view=projects`. All primary pages share `src/components/sidebar.tsx`; browsing filters are URL-backed and polling uses `router.refresh()`.
- Global agent setup inventory lives under `src/lib/agent-inventory/` and is read live by `/agents`; it never enters SQLite or the session collector. Provider readers must stay allowlist-based: return names, enabled/install status, packaging, provenance, repositories, safe paths, warnings, and global instruction Markdown, but never MCP commands/arguments/env, credentials, or raw config. Skills are deduplicated by canonical source and distinguish personal links, skills.sh lockfile installs, plugin contributions, built-ins, and unknown sources. The public discovery API takes an explicit `{ kind: "global" }` scope so future project-level discovery can reuse the model and Inventory/Compare UI without weakening the current global boundary.
- New UI must use semantic tokens and component classes from `src/app/globals.css`; do not introduce raw Tailwind palette colors, arbitrary values, inline styles, or `dark:` variants. For dynamic chart fills, use the quantized `meter-fill-N`/`spark-fill-N`/`heat-fill-N` classes instead of inline styles.

## Plan authoring rules

When a task requires an implementation plan, include `docs/superpowers/plan-dod.md` in the planning context. The final plan task must review and update `README.md` for user-facing behavior and `AGENTS.md` for architecture or convention changes. Never weaken the Definition of Done to fit a smaller task; skip a formal plan when the work does not need one.

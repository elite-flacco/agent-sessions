# UI/UX review — 2026-07-15

Scope: walkthrough of `/` (Overview), `/sessions`, `/sessions/[id]`, `/usage`, and `/agents` against live local data, cross-checked against the view components. Overall the design system is in good shape — consistent dark theme, semantic tokens, provider/status badges, honest cost labeling, sensible empty states. Findings below are ordered by impact.

Status legend: **[fixed]** addressed in the 2026-07-15 fix batch · **[partial]** core behavior addressed with follow-up work remaining · **[open]** not yet addressed.

## 1. Broken or misleading affordances

- **[fixed] Dead `selected` links from Overview.** "Running now" / "Needs attention" items linked to `/sessions?range=all&selected={id}`, but the sessions page never reads `selected`. Now link directly to `/sessions/{id}`. "Recent projects" linked to `/projects?selected={key}`; the `/projects` redirect drops the query string. Now links to `/sessions?view=projects`.
- **[fixed] Attention click-throughs lose sessions.** "Failures this week" counts `interrupted + needs_attention`, but the card and both "View all" links filtered `status=interrupted` only, so the list shown was shorter than the number promised. Added a `status=attention` pseudo-filter that expands to both statuses; the card, the panel link, and the status dropdown use it.
- **[fixed] Decorative ⌘K.** The sessions search box rendered a `⌘ K` kbd hint with no handler. Now wired to focus the search input.
- **[fixed] Dead code: `projects-view.tsx`.** The project-inspector view (consumer of `selected`) is not imported by any route since the Sessions/Projects merge. Removed.

## 2. Session title quality (biggest daily-use win)

- **[partial] Provider-authored titles are now preferred and reconciled.** Codex reads `threads.title` from the read-only `~/.codex/state_5.sqlite` database and reconciles title-only renames after each full collection pass. Claude Code prefers the latest `custom-title`, then the latest `ai-title`, before falling back to a user message. Zcode continues to use its authoritative SQLite title. Re-running `npm run collect` updates existing history.
- **[open] Fallback titles still need stronger sanitization.** Pi, Claude sessions without title records, and Codex sessions without an available database title can still fall back to noisy first-user-message text:
  - Repeated skill preambles: "Base directory for this skill: /Users/shuang/.claude/skills/commit # Commit Changes…" — many indistinguishable rows.
  - Raw ANSI escape codes: "Set model to `[1m`Sonnet 5 (default)`[22m` and saved…".
  - System noise as titles: "Command running in background with ID: …", "The user interrupted the previous turn on purpose…", and repo-list dumps.
  - Remaining fix: skip skill preambles and system-generated messages, strip ANSI/markdown, take the first message that reads as human intent, and synthesize labels such as "Commit (skill run)" when no meaningful request exists.
- **[open] Slug-like workspace fallbacks.** Non-repo sessions show derived slugs (`i-s`, `personal-ws`, `let-s-set-up-a-scheduled`) in the project column; they read as bugs. Label them as one-off workspaces (the Projects table already groups them as "Tasks").

## 3. Time presentation

- **[fixed] Bare clock time for anything <24 h.** `relativeTime` showed "8:53 PM" for yesterday evening, which reads as today — right next to a "Sessions today: 0" card. Now calendar-aware: same-day shows the time, previous day shows "Yesterday 8:53 PM", older shows the date.
- **[fixed] No absolute timestamps anywhere.** Added full date-time tooltips (`title`) on relative timestamps in the sessions table, Overview lists, and session detail.
- **[fixed] Session detail had no start date.** Header said only "Started 6:05 AM". Now shows the absolute date and time.
- **[fixed] Transcript entries were time-only across multi-day sessions** (longest session is 41 h). Day-change dividers now appear in the transcript.
- **[fixed] `runtime()` printed "0h 7m".** Zero hours dropped.

## 4. Sessions table

- **[fixed] No cost column.** Added a read-time derived cost column (`getSessionsCostUsd`, pricing-trust rule: "—" unless every usage row is priced).
- **[fixed] Subagents always expanded.** Parent rows now carry a collapsible "N subagents" toggle, default collapsed.
- **[fixed] No sorting controls.** URL-backed sort select: newest / longest / costliest first.
- **[open] All rows rendered at once** (129 in the current 7-day window). Fine locally; consider pagination or virtualization if windows grow.

## 5. Session detail

- **[fixed] Long messages render in full.** Message bodies over ~700 characters clamp with a "Show all N characters" toggle (`transcript-view.tsx`).
- **[fixed] No transcript filters or navigation.** Kind filter (All / Conversation / Tools) and a Jump-to-end control; the truncation note now says older entries remain in the source file.
- **[fixed] Subagent list rows show title + status only.** Rows now show duration and derived cost.

## 6. Responsive and narrow layouts

- **[open] Primary navigation hides destinations on narrow screens.** At 390 px the nav is a horizontally scrolling strip: "Agent setup" starts outside the visible area, with no fade, partial item, or other cue that more destinations exist. The strip can also retain an awkward horizontal position between routes. Fit all four destinations as evenly distributed icon tabs, or replace the strip with a compact menu.
- **[open] Sessions loses important scope and scan data on mobile.** The compact date-range control is hidden entirely, so the default "Last 7 days" scope is invisible and cannot be changed. Session rows also hide status, start time, duration, and cost, leaving only title/repository and the provider badge. Keep status plus relative time in the row, and move the full filter set into a compact filter sheet instead of dropping controls.
- **[open] Agent setup summaries bury the primary task on mobile.** The four provider cards become full-width stacked cards and consume almost the entire first viewport; Inventory/Compare and the filters begin below them. Put the view switcher and search first, then collapse the summaries into a compact 2x2 grid, disclosure, or horizontal card strip.

## 7. Agent setup comparison

- **[open] "Discrepancies only" is still mostly expected ecosystem noise.** The live comparison had 116 capability rows; the filter reduced it to 79 because provider-specific plugins and MCPs count as discrepancies even when no parity is expected. Separate actionable drift (personal skills, instructions, disabled/unavailable shared capabilities) from normal provider-specific differences. A selectable baseline agent or a "personal setup consistency" preset would better answer what needs fixing.
- **[open] Comparison matrix is uniformly dense — every cell expands.** Every populated cell is its own `<details>` disclosure, so the matrix reads as a wall of collapsed rows with no visual priority. Capabilities present with the same status and origin across all agents could collapse to a compact "all agents" summary, reserving disclosure for the divergent cells the discrepancy highlighting already flags. That would make "what's different" legible without expanding anything.

## 8. Smaller polish

- **[open] Overview duplicates "Running now"** as both a stat card and a panel in the same viewport; the card slot could show "Est. cost today" (currently only on `/sessions`).
- **[open] Heatmap timezone is hardcoded** to `America/New_York`; system timezone would be portable.
- **[open] Usage daily-cost strip has no date axis** (tooltips only). Add sparse day ticks or weekend shading; link bars to that day's sessions. Model rows could tag Reported vs Estimated.
- **[open] Usage project rows are not direct drill-down links.** Agent rows open provider-filtered sessions, but project rows are static and require using the generic "View projects" link. Make each project row open its matching project filter for consistent chart-to-detail navigation.
- **[fixed] Session rows expose two near-duplicate links.** Each row title links to the detail page and the adjacent external-link icon exposes another focus stop named "Open {same title} in a new tab." With long raw titles this makes keyboard and screen-reader navigation especially repetitive. Keep the secondary action, but shorten its accessible name and consider revealing it only on row focus/hover while preserving keyboard access.
- **[fixed] Sidebar fake affordances.** The profile row's `…` icon does nothing and "Settings — SOON" is a disabled button. For a single-user local tool, consider cutting the profile row; non-functional chrome erodes trust in real controls.
- **[fixed] `design-qa.md` sits in the repo root.** A one-time visual sign-off doc at the top level reads as active project metadata. Move under `docs/` to keep the root clean.

## 9. Cross-view consistency (audit pass, 2026-07-15)

The design system is strong, but several patterns are only fully realized on the Sessions page and degrade on the others. Findings here are about _parity_, not individual defects.

- **[open] Empty states vary sharply by page.** Sessions has the richest: icon + context-aware copy ("No matching sessions" vs. "No sessions indexed yet") plus a primary **Sync activity** CTA (`dashboard.tsx:505`). Session detail and Projects are medium (icon + diagnostic copy). Overview, Usage, and Agents are bare — a single `<p className="overview-empty">` line with no icon or action (Usage repeats the same text-only paragraph in three places). Lifting Overview/Usage/Agents to the Sessions pattern (icon + helpful copy + a relevant CTA) is the single highest-impact consistency fix.
- **[open] Loading/pending feedback exists only on Sessions.** Dashboard shows both a sync-button spinner (`isSyncing`) and region dimming (`isPending` → `workspace-loading` + footer "Updating…"). Overview and Usage silently `router.refresh()` every 15 s with no visual cue; Session detail and Agents get nothing during navigation. At minimum the auto-refreshing pages should show a subtle "updating" affordance so a refresh isn't indistinguishable from a hung page.
- **[open] Two filter/navigation models.** Sessions drives filters client-side (`useTransition` + URL replace, debounced search) so changes feel instant. Agents uses a native `<form method="get">` that does a full-page submit on every `<select>` change, which feels noticeably heavier. Both work; unifying toward the Sessions model would make the app feel cohesive.
- **[open] Sidebar health source differs by route.** Overview/Usage/Agents feed the connection card from `getCollectorHealth()`, while Sessions feeds it from `summary.connectedAgents` + `syncState.errors`. The same card can show different counts or error numbers depending on the page. Route every page through one source.
- **[open] No feedback loop for sync success/failure.** The Sessions sync button spins while syncing, but on completion (especially failure, e.g. a source file that won't parse) there's no transient confirmation — only the static `notice` callout when `sourceErrors > 0`. A short-lived success/error toast would close the loop.

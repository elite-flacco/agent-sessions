# UI/UX review — 2026-07-15

Scope: walkthrough of `/` (Overview), `/sessions`, `/sessions/[id]`, `/usage`, and `/agents` against live local data, cross-checked against the view components. Overall the design system is in good shape — consistent dark theme, semantic tokens, provider/status badges, honest cost labeling, sensible empty states. Findings below are ordered by impact.

Status legend: **[fixed]** addressed in the 2026-07-15 fix batch · **[open]** not yet addressed.

## 1. Broken or misleading affordances

- **[fixed] Dead `selected` links from Overview.** "Running now" / "Needs attention" items linked to `/sessions?range=all&selected={id}`, but the sessions page never reads `selected`. Now link directly to `/sessions/{id}`. "Recent projects" linked to `/projects?selected={key}`; the `/projects` redirect drops the query string. Now links to `/sessions?view=projects`.
- **[fixed] Attention click-throughs lose sessions.** "Failures this week" counts `interrupted + needs_attention`, but the card and both "View all" links filtered `status=interrupted` only, so the list shown was shorter than the number promised. Added a `status=attention` pseudo-filter that expands to both statuses; the card, the panel link, and the status dropdown use it.
- **[fixed] Decorative ⌘K.** The sessions search box rendered a `⌘ K` kbd hint with no handler. Now wired to focus the search input.
- **[fixed] Dead code: `projects-view.tsx`.** The project-inspector view (consumer of `selected`) is not imported by any route since the Sessions/Projects merge. Removed.

## 2. Session title quality (biggest daily-use win)

- **[open] Titles are raw first-user-message dumps.** The list is dominated by noise:
  - Repeated skill preambles: "Base directory for this skill: /Users/shuang/.claude/skills/commit # Commit Changes…" — many indistinguishable rows.
  - Raw ANSI escape codes: "Set model to `[1m`Sonnet 5 (default)`[22m` and saved…".
  - System noise as titles: "Command running in background with ID: …", "The user interrupted the previous turn on purpose…", scheduled-task boilerplate, repo-list dumps.
  - Suggested fix (adapter-level): skip skill preambles and system-generated messages when deriving titles, take the first message that reads as human intent, strip ANSI/markdown, synthesize labels like "Commit (skill run)" as fallback.
  - **Title-source audit (2026-07-15).** A field inventory of the raw logs found that Claude Code already records titles Relay ignores: `{"type":"ai-title","aiTitle":…}` (auto-generated, 34/69 local session files) and `{"type":"custom-title","customTitle":…}` (user-renamed, 17/69) — union 46/69 (~67%). Codex rollout files have no session title (Desktop thread titles are not written to JSONL; `payload.summary` is reasoning config), Pi has none, and Zcode's real titles come from its SQLite DB, which the adapter already uses. Revised fix: Claude adapter should prefer latest `custom-title` → latest `ai-title` → improved first-user-message heuristic; the heuristic pass (ANSI stripping, boilerplate skipping) then only carries Codex, Pi, and the Claude remainder. Re-running `npm run collect` re-titles history in place.
- **[open] Slug-like workspace fallbacks.** Non-repo sessions show derived slugs (`i-s`, `personal-ws`, `let-s-set-up-a-scheduled`) in the project column; they read as bugs. Label them as one-off workspaces (the Projects table already groups them as "Tasks").

## 3. Time presentation

- **[fixed] Bare clock time for anything <24 h.** `relativeTime` showed "8:53 PM" for yesterday evening, which reads as today — right next to a "Sessions today: 0" card. Now calendar-aware: same-day shows the time, previous day shows "Yesterday 8:53 PM", older shows the date.
- **[fixed] No absolute timestamps anywhere.** Added full date-time tooltips (`title`) on relative timestamps in the sessions table, Overview lists, and session detail.
- **[fixed] Session detail had no start date.** Header said only "Started 6:05 AM". Now shows the absolute date and time.
- **[fixed] Transcript entries were time-only across multi-day sessions** (longest session is 41 h). Day-change dividers now appear in the transcript.
- **[fixed] `runtime()` printed "0h 7m".** Zero hours dropped.

## 4. Sessions table

- **[fixed] No cost column.** Added a read-time derived cost column (`getSessionsCostUsd`, pricing-trust rule: "—" unless every usage row is priced).
- **[fixed] Subagents always expanded.** Parent rows now carry a collapsible "N subagents" toggle, default collapsed.
- **[fixed] No sorting controls.** URL-backed sort select: newest / longest / costliest first.
- **[open] All rows rendered at once** (129 in the current 7-day window). Fine locally; consider pagination or virtualization if windows grow.

## 5. Session detail

- **[fixed] Long messages render in full.** Message bodies over ~700 characters clamp with a "Show all N characters" toggle (`transcript-view.tsx`).
- **[fixed] No transcript filters or navigation.** Kind filter (All / Conversation / Tools) and a Jump-to-end control; the truncation note now says older entries remain in the source file.
- **[fixed] Subagent list rows show title + status only.** Rows now show duration and derived cost.

## 6. Smaller polish

- **[open] Overview duplicates "Running now"** as both a stat card and a panel in the same viewport; the card slot could show "Est. cost today" (currently only on `/sessions`).
- **[open] Heatmap timezone is hardcoded** to `America/New_York`; system timezone would be portable.
- **[open] Usage daily-cost strip has no date axis** (tooltips only). Add sparse day ticks or weekend shading; link bars to that day's sessions. Model rows could tag Reported vs Estimated.
- **[open] Sidebar fake affordances.** The profile row's `…` icon does nothing and "Settings — SOON" is a disabled button. For a single-user local tool, consider cutting the profile row; non-functional chrome erodes trust in real controls.
